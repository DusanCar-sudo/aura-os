# Lessons — 2026-09-16 build day (menus, mic, sidebar, calendar, files, editor)

Written for Aura so the same traps don't cost a second debugging session.
This is the distilled list.

## The failure pattern: built but never deployed
Twice, finished+committed work never reached the laptop (settings menus,
sidebar sysgraph/llmtest, popup wrapper). **A feature is done when it runs on
the live system and a screenshot confirms it** — not when it is committed.

Deploy mechanics that mattered:
- sway/waybar PATH has no `~/.local/bin`; waybar `on-click` needs absolute
  paths (`$HOME/.local/bin/...`).
- Symlink farm + scripts that resolve their own dir (`readlink -f "$0"`) means
  `git pull` is the whole update.

## Sway / waybar
- fuzzel menus need `--layer overlay`; sway stacks windows above `top`.
- Every state probe needs `timeout` — `bluetoothctl show` blocks forever with
  no controller.
- An invalid CSS property in waybar's style.css makes waybar exit; it gets
  respawned in a loop. Validate before reload. GTK CSS has no `line-height`.
- sway config warnings on reload are shown in a red bar — check `sway -C`
  before declaring a keybinding done (`$mod+E` was already "layout toggle split").
- Popups that survive mouse-leave: `focus_follows_mouse no` + an event-driven
  focus watcher (`swaymsg subscribe`), see `bin/aura-os-popup`.

## ALSA / PipeWire (the mic)
- "Mic too loud/distorted" was mixer state, not config: compare
  `amixer cget` against a known-good `asound.state` before touching configs.
- On this IdeaPad, `Mic1` = AMD digital mic (acp6x, hw:acp6x), `Mic2` = the
  SN6140 analog chip (headset jack). The Analog `Capture Volume`/`Mic Boost`
  controls only affect Mic2.
- WirePlumber rejects `wireplumber.context.properties` in conf.d drop-ins on
  this version (log: "section has no value"). Prefer `wpctl set-default`,
  which persists in `~/.local/state/wireplumber/default-nodes`.
- User-level `systemd --user` oneshot units are the way to persist mixer state
  when `alsactl store` (root) isn't available.

## Testing discipline
- **Never inject keystrokes (`wtype`) into the live session.** Focus moved to
  Brave mid-test and keys landed there. Test TUIs in a pty harness
  (`pty.fork` + `TIOCSWINSZ`); in keypad mode xterm arrows are `\eOB`, not `\e[B`.
- `pkill -f <pattern>` matches your own shell command line and kills the test
  itself. Kill by PID read from /proc.
- A stub server is the only honest way to test a measurement tool: llmtest
  against a 10 tok/s stub returned 10.0 tok/s.
- Verify claims against reality: "Bluetooth headset connected" was true while
  audio still played from speakers; only a sink listing proved the drop.

## App patterns (aura-files, aura-edit, aura-os-logo)
- One list, one column, state on the left (`[ ON ]`), never a REPL —
  see `docs/building-a-settings-tool.md`.
- Clickable TUIs: curses `get_wch` + mouse; track clickable regions per draw
  (`hits`/`tiles`), draw popups last, test clicks through the pty with SGR
  mouse escapes (`\e[<0;x;yM` / `m`).
- Notepad-style save: a centered dialog prefilled with
  `~/Documents/untitled.txt`; a directory path gets the default filename
  appended; errors in an acknowledge-box; SIGHUP/TERM with unsaved text writes
  to `~/.local/state/aura-edit/recovered/`.
- Save via temp file + `os.replace` so a crash can't truncate the target.
- New apps always get a `.desktop` entry (app list) and a keybinding that
  doesn't collide — `desktop-file-validate`, and `sway -C` for bindings.
- The block logo lives in `bin/aura-os-logo` (`rows=(`); theme colours come
  from `~/.config/waybar/theme.css`; the tagline PNG regenerates when the
  accent changes (stamp file in ~/.cache).
- Commas in sway commands sent over IPC split into separate commands: quote
  the list (`swaymsg 'for_window [..] "a, b"'`, `bindsym … "focus, exec x"`).
  Config files are fine as-is.
- sway decides where a floating window goes; a menu at the cursor opens tiny
  and invisible with `move position cursor`, reads the pointer position on
  entry (sway clamps at edges), then moves and resizes itself by `con_id`.
  egui's InnerSize is ignored there — `resize set` after the window maps.
- Test pointer UIs in a private headless sway (own XDG_RUNTIME_DIR, `vptr`,
  `grim -o HEADLESS-1`); never synthetic input on the live session.
  Full write-up: `/mnt/bigdata/solutions/2026-10-02-aura-right-click-menu.md`.
- A settings change that only goes through `swaymsg` is gone at next login;
  anything the user arranges must also be written to `config.d` (screens:
  `70-displays.conf`, keyed by make/model/serial). Saved positions go stale
  when a screen's resolution changes — re-save after mode changes.
- Scripts started from waybar or sway get a PATH without `~/.local/bin`;
  anything they launch from there fails silently (the file tree "never
  worked" for this reason). Prepend it, or use full paths. Place floating
  panels from the focused workspace's rect, not the output rect minus a
  hard-coded bar height — bars change size.
- waybar can't be resized by dragging, but a layer surface with exclusive
  zone 0 is placed where the bars' reserved space ends, so a 6 px strip
  sits on the sidebar's edge with no tracking. The width lives in an
  `"include"`d file and SIGUSR2 reloads it. Test waybars need their own
  `dbus-run-session`, or SIGUSR2 crashes them (GApplication clash).
